# 大玉トマト農園シミュレーションRPG 要件定義書

> 本書は、カイロソフト「大空ヘクタール農園」風の経営シミュレーションRPGを、**大玉トマト × ビニールハウス特化**というテーマで Web ブラウザ向けに開発するための要件定義書である。
>
> - 対象読者: 企画・開発・デザイン・将来の協力者
> - 状態: **初版確定**（フェーズ1=MVP は実装着手可能なレベル、フェーズ2=拡張は方向性レベル）
> - 言語: 日本語 / Markdown

---

## 1. ゲーム概要

### 1.1 一言コンセプト
**「大玉トマトだけを極める、ビニールハウス農園経営シミュレーションRPG」**

### 1.2 ジャンル
シミュレーション + 経営 + 軽量RPG（農園主と従業員の育成要素）。

### 1.3 ターゲットプレイヤー
- カイロソフト作品（大空ヘクタール農園、開発物語、ゲーム発展国++ など）が好きな層
- ブラウザで隙間時間に遊べる経営シムを探している層
- 1作物に絞り込んだ「やり込み特化」を楽しめる層

### 1.4 想定プレイ環境
- **フェーズ1（MVP・開発検証）**: PC / スマホのモダンブラウザ（Chrome / Safari / Edge / Firefox 最新版）
- **将来配信形態**: **iOSアプリ（有料配信）** を最終ゴールとする。**Capacitor 等で Web 実装をネイティブラッパー化する案を第一候補**とし、必要に応じて React Native や SwiftUI 移植も後で比較検討する（技術選定は MVP 完成後）。ブラウザ実装段階から**スマホ縦持ち / タップ操作を一級市民として設計**する。
- 1セッション 5〜15 分、長期プレイで 10 時間以上

### 1.5 マネタイズ方針
- **現時点ではマネタイズしない**（開発検証フェーズ）。
- 将来的に **iOSアプリで買い切り有料配信**。App Store 申請を想定し、サードパーティ素材のライセンス管理・利用規約への抵触回避（実在品種名や実在企業名の不使用など）を初期から徹底する。
- 課金アイテム・広告は当面**入れない**方針。

### 1.6 カイロ作品との関係と差別化
- **類似点**: グリッド配置、施設拡張、雇用、研究、評価、年単位の進行、ドット絵の世界観
- **差別化**: 作物を**大玉トマトのみ**に絞ることで、品質グレード・品種改良・栽培技術・市場戦略に深く踏み込む。「広く浅く」ではなく「狭く深く」のカイロ風。

## 2. ゲームのコアループ

```
[1] ハウスを建てる
        ↓
[2] 大玉トマトの苗を植える
        ↓
[3] 毎日の管理（水やり・追肥 ／ 摘芯・温度調整はフェーズ2）
        ↓
[4] 収穫（量と品質グレードが決まる）
        ↓
[5] 出荷・販売（市場価格 × グレード × 量）
        ↓
[6] 収益で拡張・研究・雇用 ──→ [1] へ戻る
```

このループを**1日〜1週間で1周**まわせることを目標にする。

## 3. 時間進行（リアルタイム制）

本作はターン制ではなく**実時間連動のリアルタイム進行**を採用する。

### 3.1 タイムスケール
- **基準: 現実の 1 秒 = ゲーム内 3 分**。
- これに従う換算表:

| 現実時間 | ゲーム内時間 |
| --- | --- |
| 1 秒 | 3 分 |
| 20 秒 | 1 時間 |
| 1 分 | 3 時間 |
| 8 分 | 1 日（24 時間） |
| 約 53 分 | 1 週間（7 日） |
| 約 4 時間 | 1 季節（30 日） |
| 約 16 時間 | 1 年（120 日 = 4 季節 × 30 日） |

### 3.2 1日と季節の構造
- 1ゲーム日 = 24 時間。日付・時刻は連続的に進む。
- 1日は描画・演出上 **朝 / 昼 / 夕 / 夜** の4時間帯に分かれる（時間帯は環境光と作業効率に影響）。
- 1ゲーム年 = **春 / 夏 / 秋 / 冬 の4季節**、各季節 30 日（合計 120 日 / 年）。
- 季節で気温・日照・電気代が変動し、ハウス内環境への影響度が変わる（夏は高温障害、冬は加温コスト）。

### 3.3 オート進行と一時停止
- ゲームを開いている間、時計は**自動で進む**。
- **一時停止 / 2倍速 / 4倍速 / 8倍速** の速度切替を提供（待ち時間を縮める手段）。
- バックグラウンド（タブ非アクティブ / アプリ最小化）時の挙動:
  - **MVP**: タブが戻った時に「最後の保存時刻からの経過時間ぶん」を一括シミュレートして追いつかせる（オフライン進行）。
  - 不正改竄対策として、システム時計の極端な巻き戻しは検知して進行を抑止。

### 3.4 作業アクションのテンポ感
- プレイヤーが連続して何かを操作し続ける必要は無く、**「種を撒いて放置 → 通知や見回りで対応」** のテンポを基本とする。
- 主要アクション（水やり/追肥/収穫など）は**1タップで完結**し、長押し UI などは持たない。

## 4. ゲームシステム — フェーズ1（MVP）

> MVP の到達目標: **「ハウスを建てる → 大玉トマトを育てる → 売る → 拡張する」が一通り成立し、農園主のレベルアップが体感できる**こと。

### 4.1 ビニールハウスシステム
- 農園は**グリッドマップ**（例: 16×12 マス）として表現。
- プレイヤーは空きマスに**ビニールハウス**（1棟=2×3マス想定）を建設。
- ハウスには**栽培区画（Plot）が複数**含まれる（例: 1棟 = 6 区画）。
- 初期コスト、維持費（光熱・資材）を持つ。
- MVP ではハウスは1種類のみ。

### 4.2 大玉トマト栽培システム
- 1区画に 1株（または 1ロット）の大玉トマトを植える。
- **生育ステージ**: `播種 → 発芽 → 育苗 → 定植 → 開花 → 着果 → 肥大 → 収穫期`
- 各ステージは所定日数で進行し、適切なアクションを取らないと品質・収量が下がる。
- 必須アクション（MVP）:
  - **水やり**: 不足で枯死/品質低下、過剰で根腐れ
  - **追肥**: 着果〜肥大期にかけて品質を底上げ
- 任意アクション（拡張余地として後述）: 摘芯、誘引、温度調整など

### 4.3 収穫と品質
- 収穫量（kg）と品質グレード（**S / A / B / C**）が決まる。
- グレードを決めるパラメータ（MVPでは下記のみ）:
  - 管理スコア（水やり/追肥の的確さ）
  - ハウス性能（MVPでは固定）
  - 農園主の栽培スキル補正
- 各グレードに**期待単価**を設定し、単価差を体感できるバランスにする。

### 4.4 出荷・販売
- 収穫物は**在庫**に入る。
- 出荷画面で**ロット単位で出荷**し、即時換金。
- 市場価格は MVP では固定（フェーズ2で変動制）。

### 4.5 経済システム
- 通貨は1種類（円）。
- **支出**: 種苗、肥料、ハウス建設、修繕、（将来）給与・電気代
- **収入**: トマト出荷
- 残高がマイナスになる演出（借入 / ゲームオーバー）は MVP では持たず、**0円で停止**する穏やかな失敗にとどめる。

### 4.6 プレイヤー（農園主）の成長 — RPG要素
- 農園主は **レベル / 経験値 / スキル** を持つ。
- **経験値の獲得源**: 出荷、収穫、研究（将来）、イベント達成
- **基本スキル（MVP）**:
  - **栽培スキル**: 品質グレード補正 + ステージ進行誤差吸収
  - **経営スキル**: 出荷単価ボーナス、建設コスト割引
  - **目利きスキル**: 種苗の優良ロット取得確率
- レベルアップ時に**スキルポイント**を獲得し、任意のスキルに振る。
- レベルに応じて建設可能なハウス数の上限・解放要素を制御。

## 5. ゲームシステム — フェーズ2（カイロ風フルセット拡張）

> MVP の手応えがあれば順次追加。**優先順位は 10章のロードマップ**で管理する。

### 5.1 従業員システム（RPGパーティ風）
- ハローワーク的画面で**従業員を雇用**。
- 各従業員は固有の **職業 / レベル / スキル / 特性 / 給与** を持つ。
- 職業例: **栽培士・技術者・営業・研究員・運送員・アルバイト**
- ハウスや出荷場に**配置**することで効果を発揮（自動化、品質補正、研究促進等）。
- 経験値で**レベルアップ**し、ステータスが伸びる（パーティ育成感）。

### 5.2 研究開発
- 研究員配置とポイント蓄積で**技術ツリー**を解放。
- 技術例:
  - **潅水自動化**（水やり作業を不要化）
  - **養液栽培**（収量↑）
  - **補光 LED**（冬季の生育↑）
  - **CO2 施用**（糖度↑）
  - **総合環境制御**（複合効果）

### 5.3 品種改良
- 大玉トマトには**系統**がある。**品種名はすべて架空名**とし、実在の登録品種名（桃太郎・麗夏・ルネッサンス等）は使用しない（将来の有料配信時の権利リスク回避）。
- 架空系統の例（仮）: **「アカネ丸」「ヒカリ玉」「コハク」「ユウヒ赤」「サンセット王子」**…のように、和風 + イメージ語で命名する。
- 系統ごとに固有パラメータ（**糖度・玉伸び・耐病性・収量**）。
- 2系統を**交配**して新系統を作る。固定化までに数世代必要。
- プレイヤーは新系統に自由に命名できる（**ユーザー命名はサーバ送信せずローカル保存のみ**）。命名・登録によって市場プレミア（特産品扱い）を獲得。

### 5.4 施設拡張
- **高級ハウス**: ガラス温室、高軒高ハウス（性能↑、コスト↑）
- **設備**: 自動潅水、ヒートポンプ、選果機、出荷場、研究棟、休憩室
- 設備によって従業員の効率や品質グレード分布が変わる。

### 5.5 環境・リスク
- **気象**: 季節 × 天気（晴/曇/雨/雪/台風/寒波/猛暑）
- **病害虫**: うどんこ病、灰色かび病、コナジラミ、トマトキバガ等
- 対策（防除、品種選定、設備強化）と被害（収量↓・品質↓）でゲームに揺らぎを生む

### 5.6 イベント・評価
- **市場相場の変動**（季節要因 + ランダム）
- **品評会・コンテスト**（特定グレードを揃えて出品 → 賞金 + 評判）
- **メディア取材・地元祭り**
- **農園評価値 / ファン数**: 出荷量・品質・受賞で増加し、来客や価格にボーナス

### 5.7 ストーリー / 目的モード
- 年次目標（例: 3年目までに ○○ 万円達成、5年目に農林大臣賞）
- エンディング条件と「2周目以降の引き継ぎ」
- 自由モード（無期限プレイ）と挑戦モード（年数制限）

## 7. データモデル / セーブシステム

### 7.1 主要エンティティ（概念設計）

> TypeScript 風の擬似コードで主要エンティティを示す。最終的なフィールドは実装時に確定。

```ts
// ゲーム全体の状態（セーブ単位）
type GameState = {
  version: number;             // スキーマバージョン (v1 始まり、7.2.3 参照)
  player: Player;
  farm: Farm;
  market: MarketState;
  weather: WeatherState;
  research: ResearchState;     // フェーズ2
  employees: Employee[];        // フェーズ2
  clock: {
    year: number;
    season: Season;
    day: number;           // 1-30
    hour: number;          // 0-23
    minute: number;        // 0-59
    speed: 0 | 1 | 2 | 4 | 8;  // 0 = 一時停止
    lastTickAt: number;    // 最後にtickした実時刻 (ms epoch)
  };
  events: EventLog[];
};

type Player = {
  name: string;
  level: number;
  exp: number;
  skillPoints: number;
  skills: { cultivate: number; business: number; appraisal: number };
};

type Farm = {
  width: number;
  height: number;
  cash: number;
  greenhouses: Greenhouse[];
  inventory: HarvestStock[];   // グレード別在庫
};

type Greenhouse = {
  id: string;
  position: { x: number; y: number };
  size: { w: number; h: number };
  tier: number;                // フェーズ2で性能差
  plots: Plot[];
};

type Plot = {
  id: string;
  plant?: TomatoPlant;
  waterLevel: number;          // 0-100
  fertilizerLevel: number;     // 0-100
};

type TomatoPlant = {
  varietyId: string;
  stage: GrowthStage;          // 'seed' | 'sprout' | ... | 'harvest'
  daysInStage: number;
  careScore: number;           // 管理の累積評価
};

type TomatoVariety = {
  id: string;
  name: string;
  sweetness: number;
  size: number;
  disease: number;
  yield: number;
};

// フェーズ2
type Employee = {
  id: string;
  name: string;
  job: 'cultivator' | 'engineer' | 'sales' | 'researcher' | 'driver' | 'parttime';
  level: number;
  exp: number;
  skills: Record<string, number>;
  assignedTo?: string;          // greenhouse id 等
  salary: number;
};

type MarketState = { basePrice: Record<Grade, number>; trend: number };
type WeatherState = { today: WeatherKind; forecast: WeatherKind[] };
type Grade = 'S' | 'A' | 'B' | 'C';
type Season = 'spring' | 'summer' | 'autumn' | 'winter';
type TimeOfDay = 'morning' | 'noon' | 'evening' | 'night';  // 表示・ライティング用に時刻から導出
type GrowthStage = 'seed' | 'sprout' | 'seedling' | 'planted' | 'flower' | 'fruit' | 'grow' | 'harvest';
type HarvestStock = { grade: Grade; kg: number };
type EventLog = { day: number; kind: string; message: string };

type ResearchState = { points: number; unlocked: string[]; current?: string };
```

### 7.2 セーブシステム

#### 7.2.1 設計方針
- **いつでも続きから再開できる**ことを最優先とする。
- 「サーバ無し」でも「コードのコピペ」で別端末・別ブラウザ・将来のiOSアプリへ**自前で持ち運べる**ことを必須機能とする（クラウドアカウントを作らせない）。
- **3 層構成**で運用する:

| 層 | 役割 | 形式 | タイミング |
| --- | --- | --- | --- |
| ① 自動セーブ | 中断・復帰の主役 | `localStorage` に JSON | 一定間隔（例: 30 秒）/ 重要イベント時 |
| ② スロットセーブ | 任意の名前付きセーブ（3〜5 枠） | `localStorage` に JSON | プレイヤー操作 |
| ③ **持ち運びコード**（エクスポート/インポート） | 別端末への引き継ぎ・バックアップ | テキスト文字列（後述） | プレイヤー操作 |

#### 7.2.2 持ち運びコード（コピペ式セーブ）
プレイヤーの「コピペで途中から開始したい」要望に対応する**正式機能**として実装する。

- 「エクスポート」を押すと、`GameState` を以下のパイプラインで文字列化して表示し、**「コピー」ボタン**でクリップボードに送る。
- 「インポート」では文字列を貼り付けてロードする。

```
GameState (JS object)
  → JSON.stringify
  → LZ-String 等で圧縮（Base64-URL 安全文字列を出力）
  → 先頭にバージョンタグ + チェックサムを付与
  → 表示用に 4〜5 文字ごとに区切る（任意）

例:  TTG1-v1-a1b2-LZ:XQAA...チェック:7F3C
     ^^^^ ^^                       ^^^^^^^^^
     接頭辞・スキーマver           CRC32等のチェックサム
```

- **バージョンタグ**（例: `v1`）でセーブ形式の世代を識別。読み込み時に**マイグレーション関数**を通して旧形式から最新形式へ変換する（後方互換）。
- **チェックサム**（CRC32 など）で改竄・破損を検出。一致しなければ警告のみ出してロードは試行する。
- 暗号化はしない（ユーザーが自分のセーブを覗ける方が便利）。ただし将来 iOS 有料配信時に「不正な極端値」（所持金が天文学的等）を弾く健全性チェックを軽く入れる。
- データサイズの目安:
  - フェーズ1で**おそらく 1〜3 KB 未満**（圧縮後）→ 数百文字のコードで収まる
  - フェーズ2拡張でも **5〜10 KB 程度**（圧縮後数千文字）に収める設計を目指す
- スマホで貼り付けが辛い長さになった場合に備え、フェーズ2で **QRコード表示 / 読み取り**による引き継ぎを追加検討。

#### 7.2.3 セーブの互換性とバージョン管理
- `GameState.version` フィールドは**整数のスキーマバージョン**（v1, v2, …）。マーケティング用バージョン（1.0.3 など）とは独立。
- マイグレーション関数を**チェーン**で持つ: `v1→v2→v3` …。古いセーブを開いたら必要なだけ順に適用する。
- 破壊的変更（例: フィールド名変更）の場合は変換ロジックをコード内に常駐させ、削除しない（過去セーブが永続的に読める状態を維持）。
- セーブ読み込み失敗時は**プレイヤーに原文をダウンロード**できるボタンを提示し、データを失わせない。

#### 7.2.4 オフライン進行との関係
- 3 章で定義した「タブを閉じている間の経過時間ぶんをシミュレート」する処理は、セーブに保存された `clock.lastTickAt` と現在実時刻の差分で計算する。
- 持ち運びコードでインポートした場合は `lastTickAt` を**インポート瞬間に書き換える**（端末間移動で「数日分が一気に進む」事故を防ぐ）。

## 8. 技術スタック・実装方針（推奨）

> 本章は **推奨構成** であり、実装計画フェーズで最終確定する。

| 項目 | 推奨 | 理由 |
| --- | --- | --- |
| 言語 | **TypeScript** | ゲーム状態が複雑になるため型で守る |
| ビルド | **Vite** | 軽量で開発体験が良い |
| 描画 | **HTML5 Canvas + PixiJS**（MVP は素のCanvasでも可） | ドット絵2D表現と多数スプライト描画に強い |
| UI | **DOM + CSS**（ボタンやメニュー） / Canvas（マップ） | UI は HTML、ワールドは Canvas のハイブリッド |
| 状態管理 | 単方向データフロー（reducer/イベント方式）。`GameState` を1オブジェクトに集約 | セーブ・ロード・タイムスリップが容易 |
| 保存 | **localStorage**（JSON）+ **エクスポート文字列**（LZ-String 圧縮 + Base64 + バージョンタグ + チェックサム） | 自動継続 と コピペ持ち運び を両立（7.2 参照） |
| テスト | **Vitest** | ロジック（栽培・経済）のユニットテスト用 |
| デプロイ | 静的ホスティング（GitHub Pages / Cloudflare Pages 等） | 静的サイトで完結 |

実装ディレクトリ構成・モジュール分割は実装計画フェーズで詳細化する。

## 11. アセット制作方針

ビジュアル・サウンドともに**本プロジェクト内で自作**する。AIツール（Claude / Suno AI 等）を活用しつつ、配信前にライセンス条項を再点検する。

### 11.1 ビジュアル（ドット絵）

- **カイロソフト作品風のドット絵**を、開発支援AI（Claude）に都度生成依頼し、必要に応じてユーザーが手直しする。
- 各アセットは PNG 単体ファイルでリポジトリ内 `assets/sprites/` に格納し、ライセンスはプロジェクト独占とする。
- 解像度の方針（暫定・実装着手時に最終化）:
  - マップタイル: 1マス **32×32 px**
  - キャラクタ: **16×24 px**（頭身低め、4方向アニメ）
  - UI: ピクセルフォント（日本語ビットマップフォント、または商用利用可のフォントを採用）
- カラーパレット: 16〜32 色程度の固定パレットを定義し全アセットで共有（後で差し替え容易）。
- 必要素材リスト（MVP 範囲）:
  - 農園地面タイル（土・草・道）
  - ビニールハウス外観 + 内部床
  - 大玉トマトの生育ステージ別スプライト（少なくとも 4 段階）
  - 農園主キャラ（4方向 × 待機 / 歩行 / 作業）
  - UI アイコン（水やり、肥料、出荷、設定、お金 等）
- **暫定運用**: 絵が揃うまでは**色付きの矩形 + 文字ラベル**で代用してロジックを先行検証する。アセット完成順に差し替える。
- iOS有料配信を見据え、すべての絵素材は**完全オリジナル**で、第三者の作風・既存タイトルからのトレース流用を行わない。

### 11.2 サウンド（BGM / SE）

- **本プロジェクト内で自作**する。AI ツール（**Suno AI** 等）を活用しつつ、最終的な権利は本プロジェクトに属する形で運用する。
- 利用ツールの**ライセンス条項を毎回確認**し、有料配信での商用利用が許諾される範囲でのみ使用する（無料プラン生成物の商用可否はサービスごとに異なるため、配信前に再点検）。
- ファイル配置: `assets/bgm/`, `assets/se/` 配下。フォーマットは **OGG**（Webブラウザ標準）を基本、必要に応じ MP3 も併存。
- 必要素材リスト（MVP 範囲）:
  - BGM: タイトル画面 / 農園昼 / 農園夜 / 出荷成功時のジングル
  - SE: ボタン、植え付け、水やり、収穫、レベルアップ、警告
- 暫定運用: 揃うまでは**無音**でロジック検証。完成順に差し替え。
