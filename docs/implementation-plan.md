## 1. 技術選定（最終確定）

要件定義書 8 章の推奨を実装計画として確定する。

| 領域 | 採用 | バージョン目安 | 備考 |
| --- | --- | --- | --- |
| 言語 | TypeScript | 5.x | `strict: true` |
| ビルド | Vite | 5.x | `vite create` テンプレートから派生 |
| 描画 | **PixiJS** | 8.x | スプライト多数 + ピクセル拡大に強い |
| UI | DOM + CSS（メニュー/HUD） | — | ピクセル風 CSS を別ファイルに集約 |
| 状態管理 | 自前 reducer（外部ライブラリ無し） | — | `GameState` 1オブジェクト |
| 保存圧縮 | `lz-string` | 1.5.x | 持ち運びコード生成 |
| テスト | Vitest | 1.x | ロジックのみ |
| Lint / Format | ESLint + Prettier | 最新 | `eslint-config-prettier` 併用 |
| パッケージ管理 | npm | Node 20+ | lockfile を必ずコミット |

**意図的に採用しないもの**: React/Vue（MVP の規模では過剰）、Redux/Zustand（自前 reducer で足りる）、状態同期ライブラリ、i18n（要件で日本語のみと確定）。

**設計原則**
- `game/` は**純粋ロジック**のみ。Pixi や DOM に依存しない（テスト容易性）。
- `render/`, `ui/` が `game/` を読み取る片方向。逆向きの依存は禁止。
- `save/` は `game/state.ts` 以外に依存しない。

## 3. モジュール設計の要点

### 3.1 状態とゲームループ
- `GameState` は単一の plain object として `src/game/state.ts` に保持し、reducer 経由でのみ変更。
- `tick(state, realDeltaMs)` が**唯一の時間進行関数**:
  1. `realDeltaMs × 3` で `clock.minute` を進める
  2. 各 plot に対し成長判定・水/肥料の減衰を適用
  3. ステージ遷移があれば通知を生成
- フレーム駆動は `requestAnimationFrame` で `tick` を呼ぶ。**速度倍率** は `realDeltaMs * speed` を渡すだけ。

### 3.2 オフライン進行
- アプリ起動時に `Date.now() - state.clock.lastTickAt` を計算し、その差分を `tick` に**まとめて渡す**だけで自動的に追いつく。
- 24 時間以上の差分は上限を設けて巻き戻し攻撃を防ぐ（要件 3.3 と整合）。

### 3.3 セーブ
- 自動セーブ: `state` を JSON 化して `localStorage["ttgame.auto"]` に書き込み（debounce 1 秒）。
- 持ち運びコード: `encode(state)` → `JSON.stringify` → `lz-string.compressToBase64` → `"TTG1-v{n}-{checksum}-{payload}"`。
- マイグレーション: `migrations[v1→v2](state)` を順に適用。MVP では `v1` のみ存在。

### 3.4 描画とアセット未完成の扱い
- スプライトが未到着の場合は `PIXI.Graphics` の矩形 + テキストで暫定描画。
- スプライトキー（例: `"tomato.stage3"`）を介する**アセットレジストリ**を用意し、PNG 差し替えだけで切り替わる構造にする。

### 3.5 UI
- 上部 HUD と下部メニューは DOM 要素として `index.html` に配置し、CSS で常時表示。
- モーダル（出荷、設定、セーブ）はオーバーレイ DOM。
- Canvas（PixiJS）は中央に固定 + `object-fit: contain` で縦持ち優先のレイアウト。

### M5: 収穫と出荷

### M6: 農園主の成長
- 経験値・レベル・スキルポイント振り UI

### M7: セーブ / ロード / 持ち運びコード

### M8: ゲーム内お知らせ

- **完了条件**: 水切れ・収穫期到達などが画面で気付ける

## 6. テスト戦略

- **ユニットテスト（Vitest）**: `game/*` の純粋関数を中心に。`tick`、`harvest`、`shipping`、`migrations` をカバー。
- **スナップショットテスト**: 持ち運びコードのエンコード/デコードのラウンドトリップ確認。
- **手動テスト**: 各マイルストーン完了時に要件 9 章のチェックリスト該当行を埋める。
- **ブラウザ手動**: M10 で iOS Safari / Android Chrome を実機確認。
- **E2E は MVP では入れない**（Playwright は導入コストが見合わない）。

## 7. リスクと対応

| リスク | 影響 | 対策 |
| --- | --- | --- |
| ピクセル拡大表示でぼやける | 見栄え | Pixi の `scaleMode: 'nearest'` を初期化時に設定。CSS で `image-rendering: pixelated` |
| オフライン進行で長期放置すると一気に成長して破綻 | ゲーム性 | 1 回の `tick` 上限を 24 ゲーム時間に分割しループ |
| セーブのフィールド名を後から変えたくなる | 互換性 | 早期に migration 雛形を仕込み、v1 段階で「捨てフィールド」も含めて固定 |
| AI 生成ドット絵のスタイルがバラつく | 見栄え | カラーパレット PNG を Claude に毎回参考提示 |
| Suno AI 等の利用規約変更 | 配信ブロック | アセット採用時に**生成日と当時の規約スクショ**を `docs/asset-license/` に保管 |
| iOS 化時に WebGL / 音声制限に当たる | ロードマップ | Capacitor で早期に試作（フェーズ2 終盤） |
